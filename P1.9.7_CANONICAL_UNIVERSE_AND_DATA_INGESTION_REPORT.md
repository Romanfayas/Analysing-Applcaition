## 5. Price-Series Contract & TCS Rounding Resolution

### 5.1 Distinct Price-Series Contracts Enforced

The platform mathematically segregates factor consumers into 4 distinct contracts to prevent total return leakage into execution or order engines:

```
                                  Corporate Action Factor
                                             │
               ┌─────────────────────────────┼─────────────────────────────┐
               ▼                             ▼                             ▼
    [SHARE_TRANSFORMATION]         [CASH_DISTRIBUTION]          [TAX_COST_ALLOCATION]
   (Splits, Bonus, Rights)          (Cash Dividends)             (Demerger Cost Pct)
               │                             │                             │
       ┌───────┴───────┐                     │                             │
       ▼               ▼                     ▼                             ▼
   [Nominal]     [Total Return]        [Total Return]                 [Tax Ledger]
(Price & Volume) (Price & Volume)      (Price ONLY)                (Section 49(2C))
                                       Volume Unaltered            Price OHLCV Unaltered
```

1. **Nominal Tradable OHLCV Series (`PRICE_RETURN`):**
   - **Consumer Audience:** Order execution engine, broker limits, stop-loss triggers, technical price indicators, support/resistance levels.
   - **Contract:** Unaltered by cash dividends ($F = 1.00000000$). Dilution events (splits, bonus issues) scale prices backward and scale volumes by $1 / F$ (preserving turnover $P \times V$).
   - **Database View:** `ca.v_active_nominal_price_factors`. Returns **0 rows** for TCS.
2. **Total Return Series (`TOTAL_RETURN`):**
   - **Consumer Audience:** Quantitative performance attribution, benchmark relative returns, long-term buy-and-hold wealth index.
   - **Contract:** Backward adjusted for both share transformations and cash dividends using:
     $$F_{\text{TR}} = \frac{P_{\text{cum}} - D}{P_{\text{cum}}}$$
   - **Volume Invariant:** Volume is strictly **NOT** adjusted for cash dividends.
   - **Database View:** `ca.v_active_total_return_factors`. Returns **1 row** for TCS (`0.99471203`).
3. **Tax-Cost Allocation Series (`TAX_COST_ALLOCATION`):**
   - **Consumer Audience:** Capital gains tax ledger.
   - **Contract:** Cost basis apportionment under Section 49(2C). Governed by NCLT court orders. **Strictly prohibited** from altering historical price or volume bars (`price_factor_applicable = false`).
   - **Database View:** `ca.v_tax_cost_allocations`. Returns **1 row** for `TATAMOTORS` (68.85% / 31.15%).
4. **Symbology Lineage Series (`SYMBOLOGY_LINEAGE`):**
   - **Consumer Audience:** Symbology mapper and identifier resolution.
   - **Contract:** 1:1 ticker renaming. Price factor strictly 1.00000000 (`price_factor_applicable = false`).

### 5.2 Forensic Investigation of TCS Rounding Discrepancies (Oct 7 & Oct 12)

#### Reported Discrepancy
- **October 7, 2026:** Nominal close = `2080.3000`. Populated adjusted close = `2069.2996`.
- **October 12, 2026:** Nominal close = `2125.0000`. Populated adjusted close = `2113.7632`.
- **Verified Primary Factor:** Revision 3 of TCS dividend factor is `0.99471203` (derived from $P_{\text{cum}} = 2269.3000$ and $D = 12.0000$).

#### Mathematical Reconciliation & Precision Analysis

$$\text{PostgreSQL Exact Calculation: } \text{ROUND}(2080.3000 \times 0.99471203, 4) = 2069.299436... \rightarrow \mathbf{2069.2994} \quad (\Delta = +0.0002)$$

$$\text{PostgreSQL Exact Calculation: } \text{ROUND}(2125.0000 \times 0.99471203, 4) = 2113.763063... \rightarrow \mathbf{2113.7631} \quad (\Delta = +0.0001)$$

#### Root Cause Proof
Executing simulation tests across IEEE-754 precision modes proved the exact mechanism of the drift:

```python
# IEEE-754 Single-Precision (float32) Simulation
c1 = np.float32(2080.30)
c2 = np.float32(2125.00)
f32 = np.float32(0.99471203)

adj1 = c1 * f32  # Evaluates to 2069.299561... -> ROUND(..., 4) = 2069.2996 (+0.0002)
adj2 = c2 * f32  # Evaluates to 2113.763184... -> ROUND(..., 4) = 2113.7632 (+0.0001)
```

1. **Factor Precision Representation:** In earlier Go/Python ingestion pipelines, prices and factors were marshaled through 32-bit floating point representations (`float32`), introducing a 24-bit significand rounding artifact.
2. **PostgreSQL Trigger Tolerance:** The quarantine guard trigger `trg_ohlcv_daily_quarantine_guard` permitted `ABS(NEW.adjusted_close - v_expected_adj) <= 0.0005`. Because the drift ($+0.0002$ and $+0.0001$) fell within $0.0005$, the database accepted the value without error.
3. **Deterministic Rounding Policy:**
   - Multiplicative factors MUST be stored as `NUMERIC(18, 8)` in PostgreSQL and `Decimal` in Python/Go.
   - Adjusted prices MUST be computed with arbitrary precision and rounded to 4 decimals using `ROUND(close * factor, 4)` (or `ROUND_HALF_UP` in Decimal).
   - Floating point types (`float32`, `float64`) are **strictly prohibited** in the adjustment calculation path.
