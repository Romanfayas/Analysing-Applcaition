## Task 1 — Runtime Database Identity Verification

### 1.1 Discovery of Deployment Configuration Defect
Inspection of `docker-compose.yml` revealed that while Migration 20 created the `halal_app_user` role, the container definitions for `backend`, `worker`, and `quant` were still templated with:
```yaml
- DATABASE_URL=postgres://${POSTGRES_USER:-halal_user}:${POSTGRES_PASSWORD:-devpassword}@postgres:5432/${POSTGRES_DB:-halal_equity}?sslmode=disable
```
When queried directly inside the running containers, `SELECT current_user, session_user` returned `('halal_user', 'halal_user')` (superuser).

### 1.2 Remediation Implemented
1. **Migration 21 Deployed**: Authored and applied `backend/migrations/21-p195-runtime-least-privilege-app-user.sql` and `quant/migrations/21-p195-runtime-least-privilege-app-user.sql`.
   - Configured `ALTER ROLE halal_app_user SET search_path = public, ca;`.
   - Granted operational DML on application tables (`paper_*`, `portfolios`, `users`, `shariah_screenings`, `ipos`, `ohlcv_daily`, etc.).
   - Granted `SELECT` on all views and tables in schema `ca`.
   - Granted DML on corporate action evidence tables to enable triggers (`trg_ca_factor_guard`, `ca_factor_ingest_guard`, `trg_ca_event_verification_guard`) to enforce security invariants.
   - Revoked `CREATE` on `public` and `ca` schemas from `halal_app_user` and `PUBLIC`.
2. **`docker-compose.yml` Updated**:
   - Replaced service database connection strings with `${APP_DB_USER:-halal_app_user}:${APP_DB_PASSWORD:-app_password}`.
   - Provided isolated `ADMIN_DATABASE_URL` strictly for scratch/disposable test fixtures in the quant service.
3. **Services Recreated**: Executed `docker compose up -d backend worker quant`.
