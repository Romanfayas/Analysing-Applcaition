# P0.7_INGESTION_DATA_FLOW_AUDIT.md

## Data Flow Trace: Yahoo Finance to PostgreSQL

**Objective:** Trace the exact code path responsible for the ingestion worker's log message `"fetched=X stored=Y"` and identify the exact persistence target.

### 1. Fetch Function
The ingestion begins in `backend/internal/workers/ingestion/pipeline.go` within `func (p *Pipeline) IngestSymbol(ctx context.Context, symbol string, name string) (IngestReport, error)`.
It attempts to fetch data by calling:
```go
dataPoint, err = p.marketProvider.GetIntradayCandles(ctx, symbol, "NSE", "1m", from, to)
```
This maps directly to `backend/internal/providers/marketdata/yahoofinance/provider.go`, which handles making the HTTP request to `https://query1.finance.yahoo.com/v8/finance/chart/...`.

### 2. Returned Data Structure
The fetch function returns a `*marketdata.DataPoint[[]models.OHLCV]`. This includes a slice of `models.OHLCV` struct representing parsed market data (Timestamp, Open, High, Low, Close, Volume).

### 3. Timestamp/Interval Metadata
- **Interval:** The interval is defined explicitly as `"1m"` when calling `GetIntradayCandles`.
- **Timestamp:** The timestamps are generated by the provider reading Yahoo's `timestamp` array from their JSON response (`time.Unix(ts, 0).UTC()`).

### 4. Persistence Function & Target SQL Table
In `pipeline.go` (Step 6), the data was historically upserted using:
```go
stored, err := p.db.UpsertOHLCVBatch(ctx, records)
```
This pointed to `backend/internal/database/repository.go` -> `UpsertOHLCVBatch`, which executes:
```sql
INSERT INTO ohlcv_daily ... ON CONFLICT (symbol_id, timestamp) DO UPDATE
```
**Conclusion from Audit:** The pipeline was falsely logging `stored++` for intraday candles because it successfully saved them, but it was polluting the historical **`ohlcv_daily`** table with minute-level records!

### 5. Stored Counter Increment Location
The `stored` integer comes directly from the successful batch execution return value of the repository:
```go
stored, err := p.db.UpsertOHLCVBatch(ctx, records)
// ...
report.CandlesStored = stored
```
And is then aggregated in `worker.go` inside the `runIngestion` loop:
```go
totalStored += r.CandlesStored
```
Therefore, the log exactly represents database persistence. However, it was persisting to the wrong table.

## Rectification Applied:
1. I created `UpsertIntradayOHLCVBatch` targeting `ohlcv_intraday` specifically (using `interval_minutes=1`).
2. Updated `pipeline.go` to use `UpsertIntradayOHLCVBatch` so the intraday pipeline now cleanly separates its writes from the daily pipeline.
